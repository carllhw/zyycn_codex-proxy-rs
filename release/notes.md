# v3.21.1

## 新增

- OpenAI 账号亲和新增“优先”模式：会话内请求优先使用主账号，繁忙或不可用时临时分流，保留原绑定，后续请求继续优先主账号

## 修复与改进

- OpenAI 首字计时采用首个非前导输出事件，包含输出项等结构事件，跳过响应创建、处理中、心跳、额度控制和失败事件；保留请求级计时起点，推理与正文仍分别按实际内容计时
- 用量列表与性能统计的 tok/s 统一按输出 Token 除以完整请求耗时计算，避免扣除首字等待后高估速率；输出 Token 保持上游口径，已包含的推理 Token 不重复相加或扣除
- 管理页面首次进入时只读取登录状态，页面活动不再触发续期；业务接口返回认证错误时共用一次续期，迟到的失败请求也等待当前续期完成后再重试
- 宽松亲和改为直接按调度策略选号，不优先会话主账号；严格模式继续让同一会话共用账号，子请求等待当前账号

## 升级事项

- 从正式版 v3.21.0 升级时自动应用 `0024_preferred_account_affinity.sql`；已有保存的亲和选项保持不变，新实例及尚未保存运行设置的初始记录采用严格模式
- 需要“优先主账号、必要时分流”的实例，请在设置中选择“优先”；自行调用管理 API 的客户端应支持 `openaiAccountAffinity` 的新增值 `preferred`
- 历史用量的 tok/s 会按新口径重新计算；已记录的首字时间保持原值，新首字判定仅对升级后的请求生效
